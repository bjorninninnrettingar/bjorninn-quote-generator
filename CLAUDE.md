# bjorninn-quote-generator

Static HTML tools + Vercel API functions for Björninn Innréttingar. Deployed at
https://bjorninn-quote-generator.vercel.app — all pages talk to Airtable through
`/api/airtable`, a server-side proxy that holds the PAT (kept out of the repo
since GitHub push protection blocks committing an Airtable PAT directly).

Rewrites live in [vercel.json](vercel.json). To add another short URL, add a
`rewrites` entry there (`source` = short path, `destination` = the `.html` file),
then commit + push — Vercel redeploys automatically on push to `main`.

**Hub pages** (2026-09-12): `/skipulag` and `/verkstaedi` exist so an Airtable
button links to *one* URL per phase instead of one per tool. Each is a small
standalone page (same dark/Kumbh-Sans visual language as `velja.html`) with two
big choice cards; both read `?recordId=` and forward it unchanged into whichever
tool is picked — `cutlist.html`, `grain.html` (`/aedar`/`/saga`), and
`labels.html` all already auto-load a project from `?recordId=recXXXX` on their
own, so the hub doesn't need any Airtable write access, just the read-only
project-name lookup for the confirmation card. Adding a third tool to a phase
later = one more `.choice` block + one more forwarded href, not a rewrite of
the hub's logic.

## API

- [api/airtable.js](api/airtable.js) — proxy for Airtable requests (holds the PAT server-side)
- [api/generate-quote.js](api/generate-quote.js) — quote PDF generation (uses `pdf-lib`, `maxDuration: 30` in vercel.json)
- [api/version.js](api/version.js) — returns the deployed `VERCEL_GIT_COMMIT_SHA` (`no-store`). `/klukka` and `/tv` both poll it every 3 min and reload when it changes, so those always-open tabs never run a stale build. `/klukka` defers the reload until it's idle on the PIN screen (`reloadPending` → `resetPin()`); `/tv` has no user interaction so it reloads immediately. First rollout onto an already-open tab still needs one manual reload (the checker has to be running to catch the *next* deploy).

## Workflow notes

- cutlist.html and labels.html are meant to be used together — see leidbeiningar.html for the intended order of operations.
- grain.html (`/aedar`) is a V1 standalone planner for veneered/woodgrain fronts, which Cutty can't nest (it rotates pieces freely and has no notion of sequential grain matching). It reads Sögunarlisti front rows + Efnislisti board sizes, groups fronts into **grain runs** by `Eyðublað` unit × rounded width `B`, expands by `M`, and auto-nests each run as one composite panel (grain axis = board length, no rotation) with a guillotine strip packer. Overlong runs auto-fall-back to side-by-side (`orient:h`) then to individual fronts. **Drag & drop on the sheet**: each run has a ⠿ handle (top-left) that drags the whole run — smooth (only the `<g>` is transformed mid-drag, layout commits on drop), snaps to trim + neighbour edges, drop on another board to move it, drop a run's edge onto a same-width run to merge. **Nothing can overlap**: `nearestFree(bi, gid, want, W, H)` — used on every run/front drop — returns the closest position where the box doesn't overlap any run (obstacle-edge candidates + a coarse grid scan, then `snapPos`); `resolveCollision` is an alias. Every structural op (rotate/split/merge/send/reconcile) runs `settleBoard`/`settleAll`. **Drag ghost**: a `#dragGhost` fixed div follows the cursor across every board during a run *or* front drag (`ghostShow/Move/Hide`), the source is dimmed to 0.22, `body.dragging` forces the grabbing cursor — so a front stays visible while you carry it to another sheet. **Snap grid**: `settings.grid` (default 25 mm, toolbar input) — runs lock to grid multiples while dragging; neighbour/trim edges stay magnetic first for tight butt joins. The "⊞ Grið" toolbar button toggles `settings.freeMove` → "✋ Frjáls færsla" = drop anywhere (0.1 mm), no grid lines, edges not magnetic. Faint grid lines drawn on the board SVG when not in free mode. Both persisted in `grain:settings`.

**On-screen board size**: `settings.boardPx` (default 440, persisted per device) drives `--board-w` on `.board-wrap`; a "Stærð á skjá" range slider in the toolbar sets it, and each `.board-wrap` also has `resize:horizontal` so you can drag its corner — a `ResizeObserver` syncs that back to the slider + settings. `#boardsCol` is `display:flex; flex-wrap:wrap` so boards sit **side by side** and wrap to the next row when they don't fit. Each run has a dark **header band inside its top edge** (`HB≈19` viewBox units) carrying the unit label + ⠿ handle, so it never collides with neighbours or clips off the board. Front-cell labels (font-size 18) are `unit · shortPartur · W×H` → `unit · W×H` → `W×H` → `#N` as space allows, drawn inside the cell below the header band (`topInset`), flat or rotated up the left edge for portrait cells. `settings.trim` defaults to 10 ("Jaðar-snyrting (sjálfg. 10)") and `loadSettings` coerces a stored 0/blank back to the default.

**Woodgrain**: each board SVG has a soft procedural woodgrain background (`feTurbulence` fractalNoise stretched vertically → brown `feColorMatrix`, ~0.32 opacity over `#171310`) so the sheet's grain direction (down the length) is always visible; per-front grain streaks sit on top. Each **front cell** is its own drag target: drop on empty board space → pops into its own single-front run at that spot; drop onto a same-width run → joins it at the nearest slot; drop back over its own run → reorders. Front rows in the side panel are HTML5-draggable to reorder within / move between runs. A run's `orient` is one of three (panel shows 3 buttons: `setOrient(gid, o)`): **`"v"` stack** (drawer bank — grain down the length, crosscut off the top in sequence); **`"s"` side by side, upright** (wing / split doors — panels left→right, grain vertical in each, figure continuing across the seams; cut as one tall piece then ripped into panels); **`"h"` rotated 90°** (grain across the board width). Geometry via `frontExtent`/`runSpan`/`runTall`; `groupWidth`/`groupLen` branch on all three. `Partur` matching `SIDEBYSIDE_RE` (`væng`) defaults to `"s"` (wing doors — horizontal pair); `KEEPTOGETHER_RE` (`væng`/`skipt`) also covers "skiptur frontur" (vertical split) which stays `"v"`. Both get `keepTogether:true` (`g.kind` = "væng"/"skiptur" for the panel label) — `normalizeGroups` re-arranges starting from the run's own orient but **never auto-splits** them. The cut plan + print sequence have a branch per orient. Grain streaks are drawn in each front cell (horizontal only for `"h"`); narrow portrait cells get the label rotated up the left edge.

**Two-step office → floor** via the `Æðaplan 📐` table (`tblzkw70E2xoX9RmK`: `Nafn` / `Tækifæri 📣` link / `Efni` = material key / `Skipulag` = layout JSON / `Staðfest ✅` checkbox — all 3 proxy allowlists + `REQUIRE_FILTER`; one row per project+material). `/aedar` (office): any edit auto-saves the layout JSON to the row as a draft (debounced 1.4s, un-ticks `Staðfest ✅`); **"✅ Staðfesta skipulag"** ticks it — but `confirmPlan()` **hard-blocks** on (a) any group not on a board (`unplacedGroups()` — those fronts would never reach the saw) and (b) any overlap (`detectOverlaps()`); only mild overflow past the trim line gets a soft "staðfesta samt?" (fine on melamine). `/saga` (floor, `FLOOR_MODE = location.pathname === "/saga"`): pick a project → loads its ticked plan (skips Sögunarlisti entirely, rebuilds groups from the JSON) → lands on the **sheet overview** (not straight into the steps — the floor plan-bar has a "▶ Byrja sögun" button); `body.floor` hides the `.office-only` toolbar buttons. The floor **can still nudge** (drag/orient) — changes save to that device's `localStorage` only, stamped with a `planSig` hash of the confirmed JSON so a re-confirm from the office wins over stale local tweaks; **"↺ Sækja staðfest skipulag aftur"** discards them. `serializePlan`/`applyPlan` carry `{board, settings, groups, layout}`. The `loadingPlan` flag stops `applyPlan`'s `reconcileLayout→saveLayout` from firing a spurious plan-save (which would un-confirm on open). Unit names: the proxy returns Sögunarlisti's `Eyðublað ✏️` link as bare ids, so `fetchUnitNames` fetches Eyðublað (`tbl0WcyHhz63pSzZX`, primary `Athugasemd`) to map id→"Sk 20-22".

**Hand-added fronts** (plan-only, never touch Sögunarlisti): "＋ front" on a group or "＋ Nýr stakur front" in the side panel adds a `manual:true` front (green dashed on the sheet, editable H/width in the panel, ✕ to remove). Tracked in `manualFronts` (`{id,groupId,unitName,w,orient,label,h}`), persisted to `grain:manual:<proj>:<key>` in localStorage and folded into `groups` by `mergeManualFronts` — survives "Núllstilla röðun". `syncManualIndex` (called from `saveLayout`) keeps the index current after drags; `serializePlan` carries `manual`/`mfId` per front so an office-added front reaches `/saga`. They appear in the cut plan / print / guide like any front. Not on the Cutty cutlist, labels, or Pöntunarlisti — for that they'd need a real Sögunarlisti row (future: duplicate an existing row rather than create, since `Efni:` is a big derived formula).

**Project filter** (`fetchEligibleProjects`): `Staða í söluferli = "🏆 Tækifæri unnið"` AND `Staða í skipulagi != "For-skipulag"` AND `Staða í framleiðslu` not in `{"Afhent (LOKIÐ ✅)", "Má Afhenda 🚚"}`.

**Front detection is material-aware** (was a Partur keyword guess): a row is a front if `FRONT_RE` matches the Partur (`frontur|blindlok|áfella|vænghurð|sökkul cover`) **OR** `p.frontMat` — which is true when the Partur has `FRE`/`FRE2` (`FRE_RE`, = cut from frontaefni) **or** the row's resolved material's `Undirflokkur 🗂️` is in `FRONT_SUBS` = `{Frontaefni, Spónlagt, Hurð}`. `materialSub(efni)` looks the Undirflokkur up from `boards` (exact norm name → startsWith → token overlap), cached in `_subCache` (cleared per project load). `fetchBoards` now also pulls `Undirflokkur 🗂️` (added to Efnislisti's proxy allowlist); the proxy returns single-selects as a bare string so the boards map does `r.fields[E_SUB]?.name || r.fields[E_SUB] || ""`. This means FRE carcase parts ("FRE - Bak/Hlið/Toppur/Botn/Föst Hilla") are now included as fronts — they're on the same æðaefni sheet and want grain continuity. **Skipped fronts**: a row that *is* front-material (`p.frontMat`) or literally `\bfrontur\b` but got dropped (missing H/B) lands in `skippedFronts` → `renderSkipped()` warning card. `MAYBE_FRONT_RE` was removed — it flagged every "Skápur hlið" (29 false positives on T-15). **New-fronts check** (`checkNewFronts`): after a saved plan loads, its pieceIds are compared against a fresh `buildGroups()`; any Sögunarlisti fronts the plan is missing show a blue "🆕 N nýir frontar" card inside `#skippedCard` with a "Bæta þeim við skipulagið" button (`addNewFronts` folds them into groups + drops on the last board + `settleAll`). **Grain detection** (`isGrainMaterial`): `Undirflokkur = Spónlagt` → grain; then décor code `H####` = woodgrain, `U####` = solid; `GRAIN_RE` species keywords are the fallback. It's only a picker sort/badge — you can still plan a "slétt" material.

**Recent UX**: `nearestFree` on every drop (no overlaps ever); undo/redo (⌘Z / `pushHistory` from `saveLayout`); confirm dialogs on "Núllstilla röðun" and "Fjarlægja plötu"; manual fronts have an editable label (`mf-label`) + `duplicateFront(gid,fi)` (⎘, works on real fronts too → makes a manual copy); `copyFloorLink()` on a confirmed plan; arrow-keys nudge the selected run by the grid step (Shift = 1 mm, Delete removes a lone manual run); guide top bar has per-board jump buttons + "N búin" count.

The sawyer drags runs, reorders/​splits/​merges, sets kerf/trim, then either **prints** (each board = one page, scaled diagram + rip/crosscut sequence) or runs **"▶ Saga með leiðsögn"** — a full-screen one-step-at-a-time guide (`buildCutPlan()` → `#guideOverlay`): per board → trim → per vertical strip: rip strip, crosscut each front off the leading edge top→bottom, with a narrower run getting a follow-up rip-to-width step; horizontal runs = crosscut block then rip into N. Each step shows the one fence/stop number big, a board mini-diagram with the cut line + piece highlighted, and the finished piece(s) to label immediately. Arrow keys / space to advance, Esc to close, progress saved in `localStorage` (`grain:guide:*`) so an interrupted sawyer resumes. Read-only (no Airtable write-back yet). Manual layout is persisted per project+material in `localStorage` (`grain:layout:*`); settings in `grain:settings`. `Efni:` (resolved decor incl. customer material) was added to Sögunarlisti's `ALLOWED_FIELDS` for this page. `normalizeGroups().fits` allows **22 mm of length slack** before splitting a grain stack (`groupLen(g) <= maxL + 22`) — better a tiny overflow past the trim line than cutting a grain-matched run in two (the far sheet edge isn't trimmed anyway); a genuine overhang still shows in the "Passar ekki á plötu" warning. The `Vígindi (timbur mynstur) 🌳` / `Stemmir 🪚` checkboxes on Sögunarlisti exist but are unused in practice, so grouping is inferred, not flagged.
- **grain.html query-string encoding**: its `airtableFetch` builds the query string with `encodeURIComponent`, NOT `URLSearchParams` — `URLSearchParams` emits `+` for spaces and `vercel dev`'s request parser does not decode `+` back to space, so `{Field Name}` refs in `filterByFormula` fail with a 422 locally (works in prod, breaks in local dev). cutlist/fraesing use `URLSearchParams` and only work because prod decodes `+`; follow grain.html's approach for any new page.
- On USB export, cutlist.html writes two fields per piece back to Sögunarlisti: `Skurðarskrá` (the `CUTLST00-N-<material>` filename it landed in) and `Skurðarnúmer` (its 1-based position in that file's piece list = the "Code" Cutty shows on the left of the piece table — one code per line, quantity is separate; Cutty keeps file order). labels.html shows `Skurðarnúmer` as the "Kóði" column so the saw operator can match a piece coming off the saw to its label row. Codes restart at 1 per file, so labels.html prefixes each run with its file number (`2·5–7`) unless the Skrá filter is already narrowed to one file. Only populated for projects run through Cutty after 2026-08-31; older projects show "–". Both fields are in `WRITABLE_FIELDS`/`ALLOWED_FIELDS` for Sögunarlisti in api/airtable.js.
- Local dev: `.claude/launch.json` has a `vercel-dev` config (port 4322) that sources `.env.local` before running `vercel dev`, since `vercel dev` does **not** load `.env.local` into the function process on its own here — confirmed by direct testing (a custom test var placed in `.env.local` never showed up in `process.env` until the launch command explicitly `source`d the file first). `AIRTABLE_TOKEN`/`WEBHOOK_SECRET` are marked Sensitive in Vercel, so `vercel env pull` returns them empty — get a real PAT from the user and write it into `.env.local` (gitignored via `.env*`) to test locally.
- When building a query string for `/api/airtable`, always percent-encode with `encodeURIComponent` (not `URLSearchParams`, which turns spaces into `+`). The incoming request parser here does not decode `+` back to space, so a `+` in a `filterByFormula` field reference (e.g. `{Field Name}`) survives as a literal plus and Airtable's formula parser rejects it as an unknown field. `api/airtable.js` also normalizes any stray `+` back to `%20` before forwarding to Airtable, as a second layer.
- Stimpilklukka (`/klukka`) reads/writes `Starfsmenn`, `Stimplanir`, `Verktímar`, `Fjarvistir`, `Orlofsbeiðnir` and reads `Tækifæri` (project list for the clock-out split) in the same Airtable base. Matching an employee's open shift is done by exact name (`{Starfsmaður}="..."`), not record ID — referencing a linked-record field in an Airtable formula resolves to the linked row's *display name*, not its ID, so `SEARCH(recordId, ARRAYJOIN(...))` silently never matches (found this the hard way — always test formula fields against real data, not just isValid).

Overridable per employee via `Starfsmenn.Vinna byrjar` / `Vinna endar` / `Vinna endar (föstudag)` (text `HH:MM`, blank = role default); the formulas branch on the `Starfsheiti` lookup + those fields (with `&""` coercion). Anything after the window, Sat/Sun, or a rauður dagur = yfirvinna. Time before the day-start is excluded from *both* (business decision) — Yfirvinna is computed from `MAX(Inn, Dagv. endir)` onward, not `Samtals − Dagvinna`. **No** Yfirvinna 1/2 rate-tier split or night rates — only the hour classification. Fixed by adding `Vinnugluggi start`/`Vinnugluggi endir` (the shift clipped to the dagvinna window) and computing the lunch overlap against *those* instead. ## HR / Launakerfi (Airtable — no Vercel)

Built 2026-08. Full chain: clock (`/klukka`) → pay period → dagvinna/yfirvinna split → holiday/sick/orlof pay → frozen monthly close → CSV for the bókari. **No employee sign-off step** — staff just get a payslip (ask for a timesheet → export from `Stimplanir`). Everything lives in Airtable: tables + formulas + one big "Run a script" step in the `MD 🗓️ - DAGLEGT ⏰` automation + one shift-created automation.

### Pay periods — 29th → 28th
- A launatímabil runs **29th of one month to 28th of the next**, labelled by the month it *ends* in (`2026-08` = 29 Jul – 28 Aug), paid the **1st** of the next month.
- Clock-in on days 1–28 → that month's period; days 29–31 → next month's.
- `Stimplanir.Tímabil` (formula) computes it; `Stimplanir.Tímabil 🗓️` (single-select, choices → 2028-12) is the same value for dropdown filtering, set by the `Stimplun → frídagur + tímabil` automation. `Launatímabil` has `Tímabil frá` / `Tímabil til` (dates) + `Tímabil 🗓️`.
- Non-leap February: that period starts 1 Mar (no 29 Feb) → a 28-day period. No days fall through the cracks.

### `Launatímabil 🧾` (`tblSQ0FfGQeBttaH2`) — one frozen row per employee per period
- Shifts + `Fjarvistir` linked in by the automation; hours arrive as rollups (`Dagvinna klst`, `Yfirvinna klst`, `Samtals klst (hrátt)` = raw Út−Inn incl. lunch — *not* payroll basis).
- `Frídagar greitt (klst)` + `Greiðir frídagar` (text list) — **paid public holidays not worked**: 7,5 Mon–Thu / 5,0 Fri / 3,75 half (Framleiðsla); 7,5 any day / 3,0 half (Sölu). Only if employed that date and no shift.
- `Veikindi greitt (klst)` — **first 2 sick days/period** (chronological, half-day = 0,5) paid at that weekday's standard hours; day 3+ unpaid.
- `Dagvinna alls (klst)` = Dagvinna rollup + Frídagar greitt + Veikindi greitt ← **the dagvinna number on the payslip / CSV.**
- `Greiddar klst` = Dagvinna alls + Yfirvinna.
- Króna: `Dagvinnulaun` (Dagvinna alls × `Kaup per klst`), `Yfirvinnulaun` (× `Yfirvinnagjald` = Kaup × 1,56), `Orlofsinneign (kr)` (`Orlofs%` × laun — paid out monthly), `Heildarlaun f. skatt`.
- Workflow: tick `Læst` → the automation copies Dagvinna alls / Yfirvinna / Greiddar / Heildarlaun into the `(læst)` fields (frozen — a paid period never changes). `Orlof-rúllun búin` guards the sick→orlof rollover from double-counting. `Staðfest af starfsmanni` fields exist but are unused.
- The bókari CSV = a grid view filtered `Læst` ✓ + `Tímabil 🗓️`, columns `Nafn · Kennitala · Dagvinna alls (klst) · Yfirvinna klst`, Download CSV. (`Kennitala` source field is a *number* → drops leading zero for anyone born on the 1st–9th.)

### Orlof — real balance on `Starfsmenn`
- Samiðn/Byggiðn seniority ladder: `Menntun` (Ekkert/Í námi/Sveinspróf/Meistarabréf) + `Ár í iðngrein við ráðningu` + `Starfsaldur hjá Björninn (ár)` → `Orlofsþrep` → `Orlofsréttur (dagar)` (24/25/27/28/30) + `Orlofs%` (10,17…13,04). Skilled (sveins/meistara) get the skilled table.
- `Orlofsdagar teknir (þ. orlofsár)` = rollup of `Fjarvistir` (Tegund=Orlof) falling in the current orlofsár (1 May – 30 Apr; `Er í yfirstandandi orlofsári` helper). `Orlofsdagar eftir` = réttur + `Orlof frá fyrra ári` + `Auka orlofsdagar 🌴` − teknir.
- **Model**: orlof % is paid out monthly (`Launatímabil.Orlofsinneign`); orlof days are planning/tracking only, they don't pay extra (the money was already paid).
- `Auka orlofsdagar 🌴` = bonus days from unused sick leave (2/month, uncapped days used doesn't go negative, **running balance capped at 10**).

### `Fjarvistir 🤒` (`tbl3e5o0Klv9RcNQ4`)
One row per employee per day. `Tegund`: Veikindi / Veikindi barna / Vinnuslys / Orlof / Launalaust leyfi / Námsleyfi / Annað. + `Hálfur dagur`, `Greitt?`, `Vottorð`, `Athugasemd`.

### Automations
1. **`MD 🗓️ - DAGLEGT ⏰`** (cron 07:00) — its 2nd "Run a script" step is the whole HR engine:
   - **Current period**: build/update `Launatímabil` daily (link shifts + fjarvistir, compute holiday/sick pay).
   - **Uppgjör**: finalize last period *once* (self-heals via `Orlof-rúllun búin`) — sick→orlof (`+MAX(0, 2 − veik)` into `Auka orlofsdagar`, cap 10), then Chat "tilbúið að læsa".
   - **Frysta**: `Læst` ticked → copy into `(læst)` fields.
   - **Reminders → Google Chat** (space `AAQAmeYUzJc`, webhook hardcoded): forgot-to-clock-out, 3+ consecutive sick days, pending `Orlofsbeiðnir`, approved leave → creates `Fjarvistir` (Orlof) rows, reynslutími/starfsafmæli within 7 days, day 28 (period ends → clock out), day 1 (review & lock), 15 Mar (unused orlof), 1 May / 1 Jun / 1 Dec (orlofsár / uppbætur).
   - `PAYROLL_TYPES = ["Fast ráðinn 👷","Verktaki 👨‍🎨","Lausráðinn "]` — only these get a launatímabil (owners/robot skipped).
   - **The MCP API can't create/edit `customScript` nodes** (`readOnlyNodeType`) — all script changes are handed to the user as paste-in-full or find/replace for the Airtable UI.
2. **`Stimplun → frídagur + tímabil`** (record created on `Stimplanir`) — matches `Inn` date to `Frídagar 📅` → sets `Frídagur` / `Hálfur frídagur`; computes `Tímabil 🗓️`.

### Deal payment split (`Tækifæri`, replaced 2 automations)
`Skipting greiðslu` (single-select: `100%` / `50% - 50%` / `40% - 30% - 30%`) + `Greiðsla 2 greidd` / `Greiðsla 3 greidd` checkboxes + `Greiðsla 1 (staðfesting)` (formula, ✅ once `Staða í söluferli = 🏆 Tækifæri unnið`) → **`Greitt (kr) 💰`** formula (`💰 Tilboðsupphæð` × ticked installment %s) + `Eftirstöðvar (kr) 💰`. Old `Það sem kúnni hefur borgað 💲` / `Eftirstöðvar greiddar` kept but unused. Interface hides Greiðsla 2/3 based on the split.

### Yearly / periodic upkeep
- Add next year's rows to `Frídagar 📅`.
- Extend `Tímabil 🗓️` choices (both `Stimplanir` and `Launatímabil`) before 2029.
- Byggiðn kjarasamningur changes → re-check the orlof ladder days/% (`Orlofsréttur` / `Orlofs%` formulas) and the 62.000 kr orlofsuppbót figure in the daily script.
- Confirm with the bókari periodically: pre-day-start time stays unpaid; orlof paid-out-monthly model; the flat dagvinna/yfirvinna split (no YV1/YV2).
