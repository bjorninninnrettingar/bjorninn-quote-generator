# bjorninn-quote-generator

Static HTML tools + Vercel API functions for Björninn Innréttingar. Deployed at
https://bjorninn.vercel.app — all pages talk to Airtable through
`/api/airtable`, a server-side proxy that holds the PAT (kept out of the repo
since GitHub push protection blocks committing an Airtable PAT directly).

**Hub pages** (2026-09-12): `/skipulag` and `/verkstaedi` exist so an Airtable

standalone page (same dark/Kumbh-Sans visual language as `velja.html`) with two

later = one more `.choice` block + one more forwarded href, not a rewrite of
the hub's logic.

## Kitchen planner (`/skipuleggja`)

HomeByMe-style self-serve planner that ends in a lead: steps intake → materials → room shape (wall chain) → **editor** → contact/submit. Submit writes Tengiliðir → Tækifæri (with the whole state as JSON in `Sjálfsafgreiðsla skipulag (JSON) 📐`) → one Eyðublað per cabinet, all through `/api/airtable` (server forces the review flag). Full history/gotchas live in the Claude memory file `project_kitchen_planner.md`.

- **Shared render module** [kitchen-planner-3d.js](kitchen-planner-3d.js) (`window.KP3D`): `CATALOG` (3 fixed-size active types + `legacy:true` oven/corner types kept so old drafts/submissions still render), `buildScene` (Three.js 3D: per-cabinet `THREE.Group`, fronts with procedural texture, door seams + handles, walls fade when between camera and room, floating-toolbar projection, cabinet/opening drag + click-select via `setupCabinetInteraction`), `buildPlan2D` (SVG plan), drag-preview helpers. Rakel's review page loads the same file with no callbacks (read-only).
- **Editor** (`screen-editor` in kitchen-planner.html): left catalog (click adds, drag drops into 3D or 2D), centre 3D/2D stage with floating toolbar and undo/redo, right panel = selected cabinet / window / door properties, or a room overview with quick material swatches. All mutations end in `refreshAfterEdit()`; state persists in `localStorage` (`bjorninn:kitchenPlanner:draft:v1`).
- **Free placement + islands** (2026-09-20): cabinets stand anywhere along a wall — `b.gapMm` = free space before a block (absent = flush; nothing auto-packs, `placeInWall`/`insertBlockAt`/`detachBlock` in kitchen-planner.html, `KP3D.blockStartsMm` is the one place offsets are computed). Arrows nudge 100 mm (Shift 10), swapping only when blocked. **Islands** = `state.islands[]` (`{id,label,lengthMm,xMm,zMm,rot,two,a[],b[]}`); `KP3D.surfacesOf(state)` returns real walls + island rows (row A, and B back-to-back) so all wall-based code (placement/drag/render/fit check) works on them; `surfaceGeoms`/`islandGeoms` are the matching geometry. Island rows are packed (no gaps) and the island's length is derived from its cabinets (`normalizeIslands()`, run in `save()`; grows from the right end); row B is measured from the far end so it gets a lead-in gap to line up with A. Slide an island with its yellow puck (3D + 2D) or the panel; catalog "Eyjar" (click = room centre, drag = drop point). Fit check warns on overlap and walkways < 900 mm. Real-mouse tests (Browser pane `computer` drags) found bugs synthetic events never did — use both.
- **Materials step = the site's own selection** (2026-09-20): [kitchen-planner-catalog.js](kitchen-planner-catalog.js) (`window.KPCAT`, generated once from the galleries on bjorninninnrettingar.is → Efnisúrval + Höldur; images in `materials/site/`, `handles/site/`) holds 49 fronts (Viðarlíki 18 / Framhliðaefni 23 / Spónlagt 8), 24 worktops (Límtré 6 / Compact 11 / Harðplast 6 / Steinn) and 14 handles. The site shows images only, so **labels are descriptive guesses from the photos — edit them in that file** (keys like `vl07`, `fh15`, `cp06` are what drafts store). `KP3D.LOOKS` merges them (old 4+1 Efnislisti looks stay as `hidden:true` for old drafts); `state.top` = worktop key (null = plain stone). Viðarlíki/límtré/compact/harðplast use the real photo texture in 3D (`imgTex`), Framhliðaefni is a satin colour, Spónlagt the procedural wood in the sampled colour. Handles are data-driven (`style` bar/edge/tab/knob/groove/none + `len` + `color`). New looks have no `efnislistiId`, so only the note to Rakel carries the choice.
- **Define your space** (2026-09-20, step 3, IKEA-style): shape cards (closed: rectangle / L-room / alcove; open: one line / corner / L, dashed = `wall.open`) → top-down drawing where any wall slides (arrows or drag) or its dimension is typed (popup with ◀ Vinstri / mm / Hægri ▶ = which end moves) → "Hvar er vatnið?" (water wall; `seedSink()` puts a Vaskaskápur there when the editor first opens). The room is a **closed rectilinear outline stored as the wall chain**: `state.closed`, per wall `lengthMm`, `turnAfter` (left = inward corner, right = reflex corner) and optional `open`. Sliding wall j by d only changes its neighbours: `len[j-1] -= d·turn[j-1]`, `len[j+1] -= d·turn[j]` (`slideLens`); `lensValid` rejects too-short walls, cabinets that no longer fit and self-intersection. 3D floor follows the outline (`ShapeGeometry`), open edges are dashed lines with no wall/skirting/cabinets/openings (`nearestWallDrop` skips them). Legacy open-chain states (old submissions on the review page) still render via `state.closed` falsy; old local drafts at shape/editor/contact are discarded on load. Only 90° walls exist — IKEA's chamfered/diagonal corner is not supported.
- **Materials = a wizard around one 3D cabinet** (2026-09-20): five pages (Skrokkur → Skúffukerfi → Framhlið → Höldur → Borðplata), each adds a level to a single spinnable 600×800×600 base cabinet (`KP3D.buildCabinetPreview/setCabinetPreview/teardownCabinetPreview`, reuses `addCabinetBox`): open box in the carcass colour → drawer bodies inside (Legra = metal grey, Merivo = white) → the cabinet closes with the front → handles → worktop. ## API

- [api/airtable.js](api/airtable.js) — proxy for Airtable requests (holds the PAT server-side)
  - **Read hardening (2026-10-01)** — the proxy is open to the internet, and three real leaks were found and closed: (1) **Tengiliðir** (all customer names/emails/phones) was readable → removed from `ALLOWED_FIELDS` (the planner only creates contacts); (2) **Tækifæri**'s "Fullt nafn 👤"/"Netfang 📧"/"☎️ Símanúmer" were in the public set → moved to `VERK_ONLY_FIELDS` (needs `?k=VERK_KEY`; kitchen-planner-review.html forwards its own `&k=`); (3) `REQUIRE_FILTER` was bypassable with `filterByFormula=TRUE()` → **every employee's PIN** was listable. Now `STRICT_FILTERS` only accepts the exact query shape each page sends (Starfsmenn: `AND({PIN 🔢}=<digits>,{Er starfandi? ✅}=1)`, Fjarvistir: must start `AND({Starfsmaður}="…",`), "PIN 🔢" is never returned, and `WRITE_ONLY` (Vefspjall, Skipulag villur) refuses GET. Also: an all-zero PIN equals a BLANK PIN in an Airtable formula, so "0000" could log in as an active employee with no PIN set — refused in the proxy, `/api/eigandi-clock` and `/api/isak-todo`. **When adding a table/field to `ALLOWED_FIELDS`, assume anyone on the internet can list it.**

- cutlist.html and labels.html are meant to be used together — see leidbeiningar.html for the intended order of operations.
- grain.html (`/aedar`) is a V1 standalone planner for veneered/woodgrain fronts, which Cutty can't nest (it rotates pieces freely and has no notion of sequential grain matching). It reads Sögunarlisti front rows + Efnislisti board sizes, groups fronts into **grain runs** by `Eyðublað` unit × rounded width `B`, expands by `M`, and auto-nests each run as one composite panel (grain axis = board length, no rotation) with a guillotine strip packer. Overlong runs auto-fall-back to side-by-side (`orient:h`) then to individual fronts. **Drag & drop on the sheet**: each run has a ⠿ handle (top-left) that drags the whole run — smooth (only the `<g>` is transformed mid-drag, layout commits on drop), snaps to trim + neighbour edges, drop on another board to move it, drop a run's edge onto a same-width run to merge. **Nothing can overlap**: `nearestFree(bi, gid, want, W, H)` — used on every run/front drop — returns the closest position where the box doesn't overlap any run (obstacle-edge candidates + a coarse grid scan, then `snapPos`); `resolveCollision` is an alias. Every structural op (rotate/split/merge/send/reconcile) runs `settleBoard`/`settleAll`. **Drag ghost**: a `#dragGhost` fixed div follows the cursor across every board during a run *or* front drag (`ghostShow/Move/Hide`), the source is dimmed to 0.22, `body.dragging` forces the grabbing cursor — so a front stays visible while you carry it to another sheet. **Snap grid**: `settings.grid` (default 25 mm, toolbar input) — runs lock to grid multiples while dragging; neighbour/trim edges stay magnetic first for tight butt joins. The "⊞ Grið" toolbar button toggles `settings.freeMove` → "✋ Frjáls færsla" = drop anywhere (0.1 mm), no grid lines, edges not magnetic. Faint grid lines drawn on the board SVG when not in free mode. Both persisted in `grain:settings`.

**On-screen board size**: `settings.boardPx` (default 440, persisted per device) drives `--board-w` on `.board-wrap`; a "Stærð á skjá" range slider in the toolbar sets it, and each `.board-wrap` also has `resize:horizontal` so you can drag its corner — a `ResizeObserver` syncs that back to the slider + settings. `#boardsCol` is `display:flex; flex-wrap:wrap` so boards sit **side by side** and wrap to the next row when they don't fit. Each run has a dark **header band inside its top edge** (`HB≈19` viewBox units) carrying the unit label + ⠿ handle, so it never collides with neighbours or clips off the board. Front-cell labels (font-size 18) are `unit · shortPartur · W×H` → `unit · W×H` → `W×H` → `#N` as space allows, drawn inside the cell below the header band (`topInset`), flat or rotated up the left edge for portrait cells. `settings.trim` defaults to 10 ("Jaðar-snyrting (sjálfg. 10)") and `loadSettings` coerces a stored 0/blank back to the default.

**Woodgrain**: each board SVG has a soft procedural woodgrain background (`feTurbulence` fractalNoise stretched vertically → brown `feColorMatrix`, ~0.32 opacity over `#171310`) so the sheet's grain direction (down the length) is always visible; per-front grain streaks sit on top. Each **front cell** is its own drag target: drop on empty board space → pops into its own single-front run at that spot; drop onto a same-width run → joins it at the nearest slot; drop back over its own run → reorders. Front rows in the side panel are HTML5-draggable to reorder within / move between runs. A run's `orient` is one of three (panel shows 3 buttons: `setOrient(gid, o)`): **`"v"` stack** (drawer bank — grain down the length, crosscut off the top in sequence); **`"s"` side by side, upright** (wing / split doors — panels left→right, grain vertical in each, figure continuing across the seams; cut as one tall piece then ripped into panels); **`"h"` rotated 90°** (grain across the board width). Geometry via `frontExtent`/`runSpan`/`runTall`; `groupWidth`/`groupLen` branch on all three. `Partur` matching `SIDEBYSIDE_RE` (`væng`) defaults to `"s"` (wing doors — horizontal pair); `KEEPTOGETHER_RE` (`væng`/`skipt`) also covers "skiptur frontur" (vertical split) which stays `"v"`. Both get `keepTogether:true` (`g.kind` = "væng"/"skiptur" for the panel label) — `normalizeGroups` re-arranges starting from the run's own orient but **never auto-splits** them. The cut plan + print sequence have a branch per orient. Grain streaks are drawn in each front cell (horizontal only for `"h"`); narrow portrait cells get the label rotated up the left edge.

**Popover round 3 — found the actual bug (2026-09-12)**: the user sent a screenshot with *both* popovers open on page load, before any click — the previous "verified working" testing only ever checked the `hidden` **attribute/property** (`p.hidden === true`), never the **computed style**, and that's exactly where the real bug was hiding. `.settings-pop { display: flex; ... }` is an *author-stylesheet* rule with no condition on it — and author CSS always wins over the browser's built-in `[hidden]{display:none}` rule regardless of specificity (origin beats specificity in the cascade). So the JS was toggling the `hidden` attribute correctly the whole time, but it never had any visual effect, on any device, ever — not a caching issue, not a device quirk, a straightforward CSS cascade bug. Fixed with `.settings-pop[hidden] { display: none; }` (class+attribute = higher specificity than `.settings-pop` alone, so it wins outright). Re-verified this time via `getComputedStyle(el).display` at every step of a real open→close cycle (was `"flex"` when open, `"none"` when closed, for both popovers, both close paths) — not just the attribute. Checked the rest of the file for the same pattern: everywhere else uses the `.hidden` *class* (`display:none !important`), which is immune to this since `!important` always wins regardless of origin — `#settingsPop`/`#morePop` were the only two elements using the bare `hidden` HTML attribute, so this was the only place the bug could hide. **Lesson for future popover/hidden-state work in this file: always assert on `getComputedStyle().display`, never just the `hidden` property** — the property can be "correct" while the element stays fully visible. User also asked whether `<details>`/`<summary>` (used for `#planMsgCard`) would be more robust here — for a simple static list, yes; for a positioned floating overlay like these two, it still needs the same "don't declare an unconditional `display` that fights the browser's own hide mechanism" discipline, so it wouldn't have been automatically bug-free either. Kept the popover pattern since the actual bug is now fixed and understood, rather than swapping patterns and re-verifying a new one right before real use.

**Drag-feel polish (2026-09-12)**, in response to "can you make the dragging movement any nicer?":
- **`#dragGhost` now transitions in/out** instead of a hard `display:none`↔`block` toggle — always in the DOM (like `#toast`), `.show` class drives `opacity`/`transform: scale(1.05)`/`box-shadow` with a `.12s` transition, giving a small "lift off the board" cue on pickup and a fade on release. `ghostShow()` only sets size/colour/text now; the *first* `ghostMove()` call after it positions the ghost synchronously (no stale-position flash) and *then* schedules the reveal one frame later so the transition has a real "before" state to animate from — get this ordering wrong (reveal before position, or position via the batched path below) and it flashes at the wrong spot for a frame.
- **Cursor tracking is now batched through one `requestAnimationFrame`** (`ghostRAF`/`ghostLast` in `ghostMove`) instead of updating `left`/`top` synchronously on every raw `pointermove` — `pointermove` can fire faster than the screen repaints, so this coalesces a burst into one paint per frame, which matters most on a slower shop tablet.
- **`pulseLanded(gid)`** — a `.4s` `landPulse` brightness-flash `@keyframes` on `.grgbox`, self-removing via `animationend`. Called after every successful drop (`enableDrag`'s and `enableFrontDrag`'s `up()`, after `saveLayout(); render();`) so a drop reads as "it landed here" instead of silently snapping into place — `render()` tears down and rebuilds every board SVG from scratch each time, so there's no DOM continuity to animate a true position transition *from*; a flash is the honest substitute. `maybeMergeOnDrop()` now returns the id the dragged run actually ended up in (was a bare `true`/`false`) so the pulse still lands on the right element when a drop triggers a merge.

- Dagvinna/yfirvinna split is computed entirely in Airtable formula fields on `Stimplanir` (`Dagv. start/endir`, `Hádegi start/endir`, `Vinnugluggi start/endir`, `Vinnugluggi (mín)`, `Háðegi skörun (mín)`, `Er frídagur`, `Er hálfur frídagur`, `Dagvinna (klst)`, `Yfirvinna (klst)`, `Samtals (klst)`) — the app never does this math client-side, and the daily HR automation only *reads* the resulting `Dagvinna (klst)` / `Yfirvinna (klst)`. **Schedule (per [Byggiðn](https://byggidn.is/vinnutimi/), overtime counted from when day work ends until it begins next morning):** `Framleiðsla` = **08:15**–16:30 Mon–Thu / 08:15–13:15 Fri, unpaid 12:00–12:45 lunch Mon–Thu. `Starfsheiti 💼 = Sölumaður / Arkitekt` = **09:00–17:00 Mon–Fri**, unpaid 12:00–12:30 lunch every weekday (30 unpaid + 30 paid rest). Overridable per employee via `Starfsmenn.Vinna byrjar` / `Vinna endar` / `Vinna endar (föstudag)` (text `HH:MM`, blank = role default); the formulas branch on the `Starfsheiti` lookup + those fields (with `&""` coercion). Anything after the window, Sat/Sun, or a rauður dagur = yfirvinna. Time before the day-start is excluded from *both* (business decision) — Yfirvinna is computed from `MAX(Inn, Dagv. endir)` onward, not `Samtals − Dagvinna`. **No** Yfirvinna 1/2 rate-tier split or night rates — only the hour classification. See **## HR / Launakerfi** below for the whole picture.
  - **Lunch must be subtracted from the clipped dagvinna window, not the raw shift.** Originally `Háðegi skörun (mín)` overlapped the lunch window against raw `Inn`/`Út`, which happened to work when the dagvinna window always contained the lunch window — but broke (went *negative*) once holidays could end the dagvinna window at/before noon. Fixed by adding `Vinnugluggi start`/`Vinnugluggi endir` (the shift clipped to the dagvinna window) and computing the lunch overlap against *those* instead. If you ever touch these formulas again, re-run the regression cases from the session that built this (~10 synthetic shifts incl. a half-holiday case) before trusting a change.
  - **Public holidays** — `Er frídagur` / `Er hálfur frídagur` now just read the `Frídagur` / `Hálfur frídagur` checkboxes on `Stimplanir` (no more hardcoded date lists). Yearly upkeep = add next year's rows to `Frídagar 📅`. Aðfangadagur / Gamlársdagur are `Hálfur dagur` (dagvinna until 12:00, afternoon yfirvinna).

  - The old `Orlofsbeiðnir 🌴` table (`tbljdg6uxEfHE7uCU`) still exists in the base with its historical records but is no longer read or written by any code or automation — safe to delete once the merged flow has been used for a cycle or two; its `Starfsmenn` backlink field (`Orlofsbeiðnir 🌴`) would need removing too.

## HR / Launakerfi (Airtable — no Vercel)

Built 2026-08. Full chain: clock (`/klukka`) → pay period → dagvinna/yfirvinna split → holiday/sick/orlof pay → frozen monthly close → CSV for the bókari. **No employee sign-off step** — staff just get a payslip (ask for a timesheet → export from `Stimplanir`). Everything lives in Airtable: tables + formulas + one big "Run a script" step in the `MD 🗓️ - DAGLEGT ⏰` automation + one shift-created automation.

### Pay periods — 29th → 28th
- A launatímabil runs **29th of one month to 28th of the next**, labelled by the month it *ends* in (`2026-08` = 29 Jul – 28 Aug), paid the **1st** of the next month.
- Clock-in on days 1–28 → that month's period; days 29–31 → next month's.
- `Stimplanir.Tímabil` (formula) computes it; `Stimplanir.Tímabil 🗓️` (single-select, choices → 2028-12) is the same value for dropdown filtering, set by the `Stimplun → frídagur + tímabil` automation. `Launatímabil` has `Tímabil frá` / `Tímabil til` (dates) + `Tímabil 🗓️`.
- Non-leap February: that period starts 1 Mar (no 29 Feb) → a 28-day period. No days fall through the cracks.

### `Launatímabil 🧾` (`tblSQ0FfGQeBttaH2`) — one frozen row per employee per period
- Shifts + `Fjarvistir` linked in by the automation; hours arrive as rollups (`Dagvinna klst`, `Yfirvinna klst`, `Samtals klst (hrátt)` = raw Út−Inn incl. lunch — *not* payroll basis).
- `Frídagar greitt (klst)` + `Greiðir frídagar` (text list) — **paid public holidays not worked**: 7,5 Mon–Thu / 5,0 Fri / 3,75 half (Framleiðsla); 7,5 any day / 3,0 half (Sölu). Only if employed that date and no shift.
- `Veikindi greitt (klst)` — **first 2 sick days/period** (chronological, half-day = 0,5) paid at that weekday's standard hours; day 3+ unpaid.
- `Dagvinna alls (klst)` = Dagvinna rollup + Frídagar greitt + Veikindi greitt ← **the dagvinna number on the payslip / CSV.**
- `Greiddar klst` = Dagvinna alls + Yfirvinna.
- Króna: `Dagvinnulaun` (Dagvinna alls × `Kaup per klst`), `Yfirvinnulaun` (× `Yfirvinnagjald` = Kaup × 1,56), `Orlofsinneign (kr)` (`Orlofs%` × laun — paid out monthly), `Heildarlaun f. skatt`.
- Workflow: tick `Læst` → the automation copies Dagvinna alls / Yfirvinna / Greiddar / Heildarlaun into the `(læst)` fields (frozen — a paid period never changes). `Orlof-rúllun búin` guards the sick→orlof rollover from double-counting. `Staðfest af starfsmanni` fields exist but are unused.
- The bókari CSV = a grid view filtered `Læst` ✓ + `Tímabil 🗓️`, columns `Nafn · Kennitala · Dagvinna alls (klst) · Yfirvinna klst`, Download CSV. (`Kennitala` source field is a *number* → drops leading zero for anyone born on the 1st–9th.)

### Orlof — real balance on `Starfsmenn`
- Samiðn/Byggiðn seniority ladder: `Menntun` (Ekkert/Í námi/Sveinspróf/Meistarabréf) + `Ár í iðngrein við ráðningu` + `Starfsaldur hjá Björninn (ár)` → `Orlofsþrep` → `Orlofsréttur (dagar)` (24/25/27/28/30) + `Orlofs%` (10,17…13,04). Skilled (sveins/meistara) get the skilled table.
- `Orlofsdagar teknir (þ. orlofsár)` = rollup of `Fjarvistir`'s `Orlofsdagur (vægi)` field (Tegund=Orlof, falling in the current orlofsár — 1 May – 30 Apr, `Er í yfirstandandi orlofsári` helper). That weight formula also zeroes out a row whose `Staða` is `Í bið`/`Hafnað`, so a pending or rejected vacation *request* row never inflates this before it's actually approved. `Orlofsdagar eftir` = réttur + `Orlof frá fyrra ári` + `Auka orlofsdagar 🌴` − teknir.
- **Model**: orlof % is paid out monthly (`Launatímabil.Orlofsinneign`); orlof days are planning/tracking only, they don't pay extra (the money was already paid).
- `Auka orlofsdagar 🌴` = bonus days from unused sick leave (2/month, uncapped days used doesn't go negative, **running balance capped at 10**).

### `Fjarvistir 🤒` (`tbl3e5o0Klv9RcNQ4`)
One row per employee per day. `Tegund` (live choices): Veikindi / Vinnuslys / Launalaust Leyfi / Námsleyfi — plus `Orlof`, which isn't a persisted choice but gets typecast-added the first time a script writes it. + `Hálfur dagur`, `Greitt?`, `Vottorð`, `Athugasemd`.

Also doubles as the vacation-request table since 2026-09-22 (merged in what used to be a separate `Orlofsbeiðnir 🌴` table) — see the "Vacation-request fields" note under the stimpilklukka bullets above for `Staða`/`Til`/`Dagar (virkir)`/`Dögum dreift`/`Orlofsdagar eftir (staða)` and the full request→approval→daily-rows flow.

### Automations
1. **`MD 🗓️ - DAGLEGT ⏰`** (cron 07:00) — its 2nd "Run a script" step is the whole HR engine:
   - **Current period**: build/update `Launatímabil` daily (link shifts + fjarvistir, compute holiday/sick pay).
   - **Uppgjör**: finalize last period *once* (self-heals via `Orlof-rúllun búin`) — sick→orlof (`+MAX(0, 2 − veik)` into `Auka orlofsdagar`, cap 10), then Chat "tilbúið að læsa".
   - **Frysta**: `Læst` ticked → copy into `(læst)` fields.
   - **Reminders → Google Chat** (space `AAQAmeYUzJc`, webhook hardcoded): forgot-to-clock-out, 3+ consecutive sick days, pending vacation requests, approved leave → expands into daily `Fjarvistir` (Orlof) rows, reynslutími/starfsafmæli within 7 days, day 28 (period ends → clock out), day 1 (review & lock), 15 Mar (unused orlof), 1 May / 1 Jun / 1 Dec (orlofsár / uppbætur).
   - `PAYROLL_TYPES = ["Fast ráðinn 👷","Verktaki 👨‍🎨","Lausráðinn "]` — only these get a launatímabil (owners/robot skipped).
   - **The MCP API can't create/edit `customScript` nodes** (`readOnlyNodeType`) — all script changes are handed to the user as paste-in-full or find/replace for the Airtable UI.
2. **`Stimplun → frídagur + tímabil`** (record created on `Stimplanir`) — matches `Inn` date to `Frídagar 📅` → sets `Frídagur` / `Hálfur frídagur`; computes `Tímabil 🗓️`.

### Deal payment split (`Tækifæri`, replaced 2 automations)
`Skipting greiðslu` (single-select: `100%` / `50% - 50%` / `40% - 30% - 30%`) + `Greiðsla 2 greidd` / `Greiðsla 3 greidd` checkboxes + `Greiðsla 1 (staðfesting)` (formula, ✅ once `Staða í söluferli = 🏆 Tækifæri unnið`) → **`Greitt (kr) 💰`** formula (`💰 Tilboðsupphæð` × ticked installment %s) + `Eftirstöðvar (kr) 💰`. Old `Það sem kúnni hefur borgað 💲` / `Eftirstöðvar greiddar` kept but unused. Interface hides Greiðsla 2/3 based on the split.

### Yearly / periodic upkeep

- Extend `Tímabil 🗓️` choices (both `Stimplanir` and `Launatímabil`) before 2029.
- Byggiðn kjarasamningur changes → re-check the orlof ladder days/% (`Orlofsréttur` / `Orlofs%` formulas) and the 62.000 kr orlofsuppbót figure in the daily script.
- Confirm with the bókari periodically: pre-day-start time stays unpaid; orlof paid-out-monthly model; the flat dagvinna/yfirvinna split (no YV1/YV2).
