# Verkstæðisappið (/app), floor tools, cutlist + labels

Moved out of CLAUDE.md on 2026-10-12.

**Verkstæðisappið — installable PWA home screen (2026-09-16)**: user asked to turn the workshop's scattered tools (stimpilklukka, active-project list, fræsing, merkingar, the skipulag/verkstaedi hubs) into one "app" instead of several separately-bookmarked/QR-reached pages, with two explicit requirements: (1) picking a project once should carry it into every tool without re-picking from a dropdown, (2) adding a quick task + assignee had to be genuinely easy — described as "stór hluti" of the ask. `/app` (app.html) is the result — a real installable PWA (`manifest.json`, `sw.js` — deliberately caches nothing, just satisfies Chrome's install criteria — and icons generated from the company logo under `icons/`, `Add to Home Screen`-able on iOS via the meta tags). Its **current project** is picked on `/verk-i-gangi` (verk-i-gangi.html, same eligibility filter as grain.html's `fetchEligibleProjects`: won + not for-skipulag + not yet delivered) and persisted in `localStorage` (`verkApp:project`) for as long as the app stays open — every tool tile (`Merkingar`→`/labels`, `Yfirfræsing`→`/fraesing`, `Skipulag`→`/skipulag`, `Saga`→`/verkstaedi`, `Verk — yfirlit`→`/verk`) forwards it as `?recordId=` (or `?t=` for `/verk`) automatically, no proxy or target-page changes needed since every one of those already auto-loads from that param. `/app` itself also accepts `?recordId=` on landing (same as the other hubs) so an Airtable button can still deep-link straight in.

*(app.html has evolved substantially since this entry — redesigned menu, per-tool project pickers, Mín síða, etc. — through commits this doc wasn't updated alongside; treat the code as the source of truth over the prose below for anything past 2026-09-16.)*

**Sög/Yfirfræsing tightened to production-ready projects only (2026-09-27)**: app.html's in-app pickers for the Sög tile (→ F6 Cutty/merkingar or F2 Vígindi/æða-leiðsögn) and the Yfirfræsing tile had used `BROAD_FILTER` (any won, not-yet-delivered project — same as `/verk-i-gangi.html`/grain.html) since 2026-09-23, deliberately, on the reasoning that cutting/milling can start before a project is formally "í vinnslu". User overrode that directly: only production-ready projects belong on those two tiles. Added `READY_FILTER` (`app.html`, next to `NARROW_FILTER`/`BROAD_FILTER`) = `{Staða í söluferli}="🏆 Tækifæri unnið"` AND `{Staða í skipulagi}="Klárt til framleiðslu"` AND `{Staða í framleiðslu}!="Afhent (LOKIÐ ✅)"` — this is exactly the filter `labels.html` and `fraesing.html` already hard-code in their own standalone project dropdowns (`fetchEligibleProjects` in each), so the in-app picker now agrees with what those pages show when opened directly with no project pre-selected, instead of a looser list that could offer a project neither page's own dropdown would ever list. `openSogList()`/`openFraesList()` now call `loadProjectList(READY_FILTER, …)`. Left untouched: `NARROW_FILTER` (Verk í vinnslu tile) and `BROAD_FILTER` (still used by the live command-palette project search, which should find any won project to open its `/verk` overview regardless of production stage).

The QUICK FIX❗ Airtable table already existed (dashboard.html reads it read-only for the TV alert bar) but had no create path — `api/airtable.js` gained `CREATABLE_FIELDS`/`FORCED_CREATE_FIELDS` (Staða forced to "opið 😠", same self-approval-proofing pattern as Fjarvistir's vacation requests) and `WRITABLE_FIELDS` (Staða only) entries for it. `/app`'s add-task form is always visible (not collapsed behind a button — the "auðvelt" requirement) with the assignee dropdown (`Ábyrgðarmaður`, the fixed 6-person singleSelect) right under the task text, optional deadline/reporter, and auto-links `Tengt verkefni` to the current project when one's selected. A "Nýleg verkefni" list right below it shows every non-`Lokið` QUICK FIX, tap-to-advance `opið → Í vinnslu → Lokið` — closes the loop without needing Airtable open. Verified end-to-end against the live base via `vercel dev` (project picked → recordId forwarded into a real labels.html load with the dropdown skipped; a real QUICK FIX created, read back, and deleted; the status-tap PATCH verified against a disposable test record, never against real in-progress rows) rather than just eyeballing the UI, since this writes to the same base every other floor tool depends on.

- cutlist.html and labels.html are meant to be used together — see leidbeiningar.html for the intended order of operations.

- On USB export, cutlist.html writes two fields per piece back to Sögunarlisti: `Skurðarskrá` (the `CUTLST00-N-<material>` filename it landed in) and `Skurðarnúmer` (its 1-based position in that file's piece list = the "Code" Cutty shows on the left of the piece table — one code per line, quantity is separate; Cutty keeps file order). labels.html shows `Skurðarnúmer` as the "Kóði" column so the saw operator can match a piece coming off the saw to its label row. Codes restart at 1 per file, so labels.html prefixes each run with its file number (`2·5–7`) unless the Skrá filter is already narrowed to one file. Only populated for projects run through Cutty after 2026-08-31; older projects show "–". Both fields are in `WRITABLE_FIELDS`/`ALLOWED_FIELDS` for Sögunarlisti in api/airtable.js.
