# PRO mode audit — 2026-10-30 (report only, nothing edited)

Scope: `kitchen-planner.html` PRO paths (`proSave*`, `proBoot`, history, Smíða wizard, Veggur view), `api/kp-pro.js`,
`kitchen-planner-worktop.js` (KPWT), `smidaFor` → `/cnc`, `api/kp-drawings.js`, `pro.html`.

## Summary (top 5)
1. **Critical — edits made while Vista is in flight are marked saved but are not in Airtable.** Reproduced against a mock: dirty flag cleared, chip "✓ vistað", reload loads the older Airtable copy → the edit is gone.
2. **Critical — in the 409 "someone else saved" dialog the default focus/Enter = "Skrifa samt yfir" (overwrite), and Enter on "Sækja nýrri útgáfu" also resolves as overwrite** (`proDialog`, line 20834). One reflexive Enter bypasses the whole two-computer guard.
3. **Critical — Afturkalla (undo) after a save reverts `state.proSavedAt` to the pre-save stamp** → next Vista sends a stale `basedOn` → false 409 "Einhver vistaði … í annarri tölvu" against yourself (reproduced; the first undo click also looks dead because only the stamp changed). Combined with #2 this is how a designer ends up overwriting her own newer work or discarding her edits.
4. **Wrong-dimension risk — worktop piece overrides are keyed by the run's first cabinet id (`p:<blockId>`)**; deleting/replacing the first cabinet of a counter run silently resets the piece's depth/overhang/cutout/joint choices to auto (reproduced: 700 → 620). In-house tops are cut from these numbers. Also: `fitPlannerJson` drops `categoryData` (other rooms) and `measurement` when the JSON is > 99 000 chars — permanent loss in Airtable, only a toast.
5. `npm test` green (fail 0). `npm run test:live` NOT run (needs `AIRTABLE_TOKEN`; I have none and did not look for one — script itself only does GETs). No console errors from the app; no horizontal overflow at 1280×800 and 1440×900; no emoji in the visible PRO UI; Cmd/Ctrl+S, beforeunload warning, 500/409 paths and the failed-save card all work.

## Findings

Fix size: S = < 10 min, L = bigger.

| # | Sev | Area | What | Size | Suggested fix |
|---|---|---|---|---|---|
| 1 | critical | Save / dirty flag | `proSaveRun` builds the request body at `fetch` time (kitchen-planner.html:20909) but after the response runs `save()` then `localStorage.removeItem(STORAGE_KEY+":dirty")` (:20937, :20945) unconditionally. Any edit made during the request (1–10 s on a big project; I used a 4 s mock) sets dirty=1 via its own `save()` and is then wiped. Result: chip says "✓ vistað", `beforeunload` stays silent, and `proBoot` (:21090 `hasLocal = proDirty() && …`) loads the older Airtable copy on next open, discarding the local newer one. Reproduced: edit plinth 91 during in-flight save → dirty null after return, server copy had 77, reopening showed 77. | S | Before the fetch take `var sent = JSON.stringify(state)` (or an edit counter bumped in `save()`); after success only remove `:dirty` if `JSON.stringify(state)` still equals `sent` (ignoring `proSavedAt`/`liSent` which the response itself changes), else leave dirty and keep chip "● óvistað". Also disable editing or queue a second save. |
| 2 | critical | 409 dialog | `proDialog` Enter handler (:20834): `done(!(activeElement.dataset.pd === "0"))`. The OK button ("Skrifa samt yfir") is auto-focused (:20838), so Enter overwrites the other save. With the middle button ("Sækja nýrri útgáfu", `data-pd="alt"`) focused, Enter also returns `true` (= overwrite) instead of `"alt"`. | S | Make Enter click the focused button (`document.activeElement.click()`), and for the 409 dialog focus "Hætta við" (or give `proDialog` an `focus:"cancel"` option) — destructive default must not be the primary. Same for the orphan "Eyða völdum línum" dialog (:19906, default-focused delete). |
| 3 | critical | Undo vs save stamp | `stepHistory` (:3146) replaces the whole `state` with a JSON snapshot, including `proSavedAt`, `liSent` (and `projSent` is server-side only). Snapshots before the last save carry the old stamp. Reproduced: edit → Vista (stamp 09:46) → Afturkalla ×2 → localStorage stamp back to 09:43 while Airtable has 09:46. Next Vista → `basedOn` older → server 409 against yourself. First undo click after a save also appears to do nothing (the snapshot pushed by `save()` after the stamp changed differs only by `proSavedAt`/`liSent`). Stale `liSent` can also fire spurious V1/V2/V3 `conflicts`. | S | In `stepHistory` re-apply the current `proSavedAt`/`liSent` onto the restored state (`var keep={proSavedAt:state.proSavedAt, liSent:state.liSent}`), and in `pushHistory` compare snapshots with these two keys stripped (like `noSk`) so a save doesn't create a dead undo step. |
| 4 | critical | Worktop (KPWT) | `compute()` keys pieces by `"p:" + firstBlock.id` (kitchen-planner-worktop.js, `pieces = runs.map…`), joints by `j:A|B`, cutouts presumably by piece. `state.worktop` is never re-keyed when cabinets are removed/reordered. Reproduced in page: `worktop.pieces["p:b1"].depthMm=700` → remove b1 → piece becomes `p:b2`, depth 620 (override silently lost; the old entry is orphaned forever). In-house worktops are cut from these sizes; joint choice also falls back to "unchosen" (Yfirferð does catch that one, not the size/overhang/cutout moves). | L | Key by position inside the surface (surface id + run index) or re-key `state.worktop.*` in `removeBlock`/insert; at minimum warn "borðplötustykki endurstillt" when an orphaned key exists. |
| 5 | critical | kp-pro size trim | `fitPlannerJson` (api/kp-pro.js:93–104) drops `measurement` (the on-site measurement!), then `proAck`, then `categoryData` (= every parked room's drawing) when planner JSON > 99 000 chars. The Line Items are written first, then the trimmed JSON overwrites the record; the page only toasts the key names (:20935). A multi-room project could lose its wardrobe/bath rooms from the saved drawing (Smíðagögn on Line Items stay). I could not measure real project sizes (no key). | L | Refuse to save (413 with explanation) instead of dropping `categoryData`/`measurement`; or compress/strip derived/bulky fields first (undo, thumbs, `liExtra`…). Measure T-32/T-199 sizes first. |
| 6 | critical | `kp-drawings` replace | With the office key the existing attachment is cleared (`PATCH {fld:[]}`, api/kp-drawings.js:69–75) BEFORE the new upload; if `uploadAttachment` then fails (502, size), the project has no drawing at all and the quote PDF loses its appendix. | S–L | Upload first, then PATCH the field to only the new attachment id (read from the upload response), or restore the old ids on failure. |
| 7 | minor→critical | Pocket doors vs quote | Smíðagögn use `proSpec()` which only honours `b.smida.doors` when `doors.length` matches the current door count (:17972) and otherwise falls back to hinged defaults; but the Revego/Concepta product + quote note read `b.smida.doors` directly (:13694–13697, :13854–13855, :20125). If the door count changes (Skipting fronta 1→2) after choosing Rennihurð, /cnc drills hinges while the Line Item still carries the pocket-door product. Static finding, not reproduced in UI. Also: hand-placed hinges are dropped on the same condition without notice. | S | Use `proSpec` (or the same length check) in those three places, and toast when custom door specs are discarded. |
| 8 | minor | PRO reset | Yfirferð → "Byrja teikninguna upp á nýtt…" runs `resetAll()` → `freshState("welcome")` (:3280). In PRO this shows the customer welcome screen ("Hannaðu heimilið þitt…") under the PRO bar, `:dirty` stays "1", `proSavedAt` is lost, so the next Vista gets a 409 that says "someone else saved" (misleading) and "Skrifa samt yfir" then overwrites the saved drawing with an empty one. Confirm text only says it deletes the design, not that Airtable's copy gets overwritten on the next Vista. Reproduced. | S | In PRO use `freshState("byrja")` + keep `proSavedAt`; confirm text: "Teikningin í Airtable breytist ekki fyrr en þú vistar". |

## What was checked and found OK
- **kp-pro.js server logic** (read in full): validation, allow-listed keys, 409 `basedOn` logic, partial-failure path (`e.partial`, client keeps `liSent`), no deletes on save (only `retire`, which refuses lines with an Eyðublað), idempotent re-save, retry of the final PATCH, 413 before any write. `tests/kp-pro.test.js` and the rest of `npm test` pass.
- **Failure UX** (mock returning 502 / 409): red `#proSaveErr` card with Reyna aftur / Velja verkefni, Icelandic text, bar chip, Esc = safe. `beforeunload` blocks navigation while dirty (Chrome logged its "no user gesture" notice on my scripted reload, expected).
- **Double submit:** `proSave` shares one in-flight promise (`pc.savePromise`); Vista button disabled while saving.
- **Veggur (2D) view**: vertical chain 100 + 1000 + 500 + 823 + 77 = 2500; horizontal 600+800+600+600 against 3600 total; no console errors.
- **Layout:** header one row, `scrollWidth == innerWidth` at 1280×800 and 1440×900 with the Smíða wizard, Tilboð panel and Yfirferð open.
- **Destructive actions with confirm/undo:** reset (confirm), orphan retire (dialog, never lines with Eyðublað), block removal (7 s Afturkalla toast, per docs).
- **Smíðagögn → /cnc:** default hinge positions come from the shared `CNCSIDES.defaultHingeSpec` for both the planner (`proDefaultHinges`) and /cnc, shelf-avoidance uses the same `proShelfRows`; only `o.doors` (explicit hinges/pocket) is sent after a door has been edited in Smíða, otherwise /cnc recomputes — consistent by construction, but there is no test that feeds a planner `smidaFor` output through `cnc-sides` for a split/pocket cabinet (that is where #7 would show).
