# Stimpilklukka (/klukka, /eigandi) + HR / Launakerfi

Moved out of CLAUDE.md on 2026-10-12.

- Stimpilklukka (`/klukka`) reads/writes `Starfsmenn`, `Stimplanir`, `Verktímar`, `Fjarvistir` (sick marking AND vacation requests, see below) and reads `Tækifæri` (project list for the clock-out split) in the same Airtable base. Each `Starfsmenn` record needs a `PIN 🔢` value set for that employee to be able to clock in/out — there's no UI for assigning PINs, set them directly in Airtable.
- `Stimplanir` is one row per **shift**, not per tap: `INN` creates a row with `Inn` set and `Út` blank; `ÚT` finds that employee's open row (`Út` blank) and PATCHes `Út` onto it. "Currently clocked in" = an open row exists. Matching an employee's open shift is done by exact name (`{Starfsmaður}="..."`), not record ID — referencing a linked-record field in an Airtable formula resolves to the linked row's *display name*, not its ID, so `SEARCH(recordId, ARRAYJOIN(...))` silently never matches (found this the hard way — always test formula fields against real data, not just isValid).
- Dagvinna/yfirvinna split is computed entirely in Airtable formula fields on `Stimplanir` (`Dagv. start/endir`, `Hádegi start/endir`, `Vinnugluggi start/endir`, `Vinnugluggi (mín)`, `Háðegi skörun (mín)`, `Er frídagur`, `Er hálfur frídagur`, `Dagvinna (klst)`, `Yfirvinna (klst)`, `Samtals (klst)`) — the app never does this math client-side, and the daily HR automation only *reads* the resulting `Dagvinna (klst)` / `Yfirvinna (klst)`. **Schedule (per [Byggiðn](https://byggidn.is/vinnutimi/), overtime counted from when day work ends until it begins next morning):** `Framleiðsla` = **08:15**–16:30 Mon–Thu / 08:15–13:15 Fri, unpaid 12:00–12:45 lunch Mon–Thu. `Starfsheiti 💼 = Sölumaður / Arkitekt` = **09:00–17:00 Mon–Fri**, unpaid 12:00–12:30 lunch every weekday (30 unpaid + 30 paid rest). Overridable per employee via `Starfsmenn.Vinna byrjar` / `Vinna endar` / `Vinna endar (föstudag)` (text `HH:MM`, blank = role default); the formulas branch on the `Starfsheiti` lookup + those fields (with `&""` coercion). Anything after the window, Sat/Sun, or a rauður dagur = yfirvinna. Time before the day-start is excluded from *both* (business decision) — Yfirvinna is computed from `MAX(Inn, Dagv. endir)` onward, not `Samtals − Dagvinna`. **No** Yfirvinna 1/2 rate-tier split or night rates — only the hour classification. See **## HR / Launakerfi** below for the whole picture.
  - **Lunch must be subtracted from the clipped dagvinna window, not the raw shift.** Originally `Háðegi skörun (mín)` overlapped the lunch window against raw `Inn`/`Út`, which happened to work when the dagvinna window always contained the lunch window — but broke (went *negative*) once holidays could end the dagvinna window at/before noon. Fixed by adding `Vinnugluggi start`/`Vinnugluggi endir` (the shift clipped to the dagvinna window) and computing the lunch overlap against *those* instead. If you ever touch these formulas again, re-run the regression cases from the session that built this (~10 synthetic shifts incl. a half-holiday case) before trusting a change.
  - **Public holidays** — `Er frídagur` / `Er hálfur frídagur` now just read the `Frídagur` / `Hálfur frídagur` checkboxes on `Stimplanir` (no more hardcoded date lists). Those checkboxes are set at clock-in by the `Stimplun → frídagur + tímabil` automation, which matches the `Inn` date against the **`Frídagar 📅`** table (`tblXoWJacAvfrXgty` — `Dagsetning`, `Hálfur dagur`; 2026–2028 seeded from fridagar.is). Yearly upkeep = add next year's rows to `Frídagar 📅`. Aðfangadagur / Gamlársdagur are `Hálfur dagur` (dagvinna until 12:00, afternoon yfirvinna).
- **Fjarvistir** (`tbl3e5o0Klv9RcNQ4`) is the absence log — one row per employee per day (`Dagsetning`, `Starfsmaður`, `Tegund`) — **and**, since 2026-09-22, also holds vacation *requests* (the old separate `Orlofsbeiðnir 🌴` table was merged in: few enough employees that two tables were unnecessary clutter). A row with `Til` filled in is a request spanning `Dagsetning` (frá) → `Til`, not a single logged day; everything else (sick marks, etc.) is a plain daily entry and never sets `Til`. The kiosk's "Tilkynna veikindi í dag" button marks *today* only (no back-dating, no multi-day range — tap again each day if out longer) and closes any currently-open shift, since sick leave doesn't require clocking in/out first. It works from any device, not just the shop kiosk — same PIN-gated `/klukka` URL. **Airtable gotcha:** a `date`-type field compared directly with `{Field}="2026-07-11"` in a formula silently matches nothing; wrap it in `DATETIME_FORMAT({Field},'YYYY-MM-DD')="..."` instead (`dateTime` fields don't have this problem, only bare `date` fields do — Fjarvistir's `Dagsetning` is a `date` field, Stimplanir's `Inn`/`Út` are `dateTime`).
  - **Vacation-request fields** (added for the merge): `Staða` (Í bið/Samþykkt/Hafnað — meaningful only on a `Til`-bearing request row; blank on a plain daily entry means "no approval needed"), `Dagar (virkir)` (formula, workday count between `Dagsetning` and `Til`), `Dögum dreift` (checkbox — set once the daily automation has expanded an approved request into individual daily rows, so it isn't expanded twice), `Orlofsdagar eftir (staða)` (lookup of the requester's own `Starfsmenn.Orlofsdagar eftir`, for visibility when a request is reviewed). `api/airtable.js`'s `FORCED_CREATE_FIELDS` forces `Staða` to `Í bið` on create **only when the payload includes `Til`** (a `(fields) => ...` function, not a static object like the other tables use) — so a self-service sick-mark, which never sends `Til`, is unaffected and doesn't need approval. `Orlofsdagur (vægi)` (the per-row weight formula that Starfsmenn's `Orlofsdagar teknir (þ. orlofsár)` rollup sums) was updated to zero out any row whose `Staða` is `Í bið` or `Hafnað`, so a pending/rejected request never counts as a taken orlof day before it's actually approved.
  - **Vacation request flow, end to end**: `stimpilklukka.html`'s "Sækja um orlof" form POSTs a Fjarvistir row with `Dagsetning`=frá, `Til`=til, `Tegund`="Orlof" (no `Staða` — server forces it). The daily HR automation's "orlofsbeiðnir" step (in `MD 🗓️ - DAGLEGT + LAUNAUTANUMHALD` → "LAUNA utanumhald" script) reminds on `Staða="Í bið"`, and once a manager flips it to `Samþykkt` in Airtable, expands the request into one daily row per workday (skipping `Frídagar 📅` holidays): the **first** matching day becomes the original row itself (`Dagsetning` updated to that day, `Til` cleared, `Dögum dreift` ticked — it's now a plain daily entry), every subsequent day is a newly created row. If the whole range has no workday in it (e.g. a weekend-only request), the row is just cleared/flagged done with nothing created.
  - **/laun** (eigandi) lists and approves these requests straight from Fjarvistir (2026-10-26 fix — until then it still read the old table below, so /klukka requests never showed up). The proxy accepts its `AND({Tegund}="Orlof",{Staða}…)` list only with the office key, and a PATCH of `Staða` only as Samþykkt/Hafnað.
  - The old `Orlofsbeiðnir 🌴` table (`tbljdg6uxEfHE7uCU`) still exists in the base with its historical records but is no longer read or written by any code or automation — safe to delete once the merged flow has been used for a cycle or two; its `Starfsmenn` backlink field (`Orlofsbeiðnir 🌴`) would need removing too.
- **Sick → vacation rollup** — Björninn's policy is 2 paid sick days/month per active employee; whatever's unused rolls into `Auka orlofsdagar 🌴` (bonus vacation days) on `Starfsmenn`, 1:1, **capped at a running balance of 10**. This is now handled entirely in Airtable by a "Run a script" step in the **`MD 🗓️ - DAGLEGT ⏰`** automation (see the full HR system — Launatímabil, holiday/sick pay, orlof engine — which lives there and in the `Launatímabil 🧾` table). The old Vercel cron `api/monthly-sick-rollup.js` was removed 2026-08 once the Airtable version took over. Paid sick days now also pay a standard day's hours into `Launatímabil`, and paid public holidays not worked do the same (`Frídagar 📅` table).
- **Grammatical gender**: `Starfsmenn.Kyn` (singleSelect, `KK`/`KVK`) drives which Icelandic verb/adjective forms stimpilklukka uses (mættur/mætt, skráður/skráð veikur/veik, stimplaður/stimpluð). Defaults to `KK` in the app (`isKK = record.fields["Kyn"] !== "KVK"`) if the field is blank for an employee — fill it in per employee directly in Airtable, no kiosk UI for it.
- **"Mínar stundir"** (self-service hours) sums the current **calendar month's** *closed* Stimplanir shifts (`{Út}!=BLANK()`) client-side — an info view only, no longer part of any confirmation flow. Note it's still calendar-month while payroll runs on 29→28 periods (`Tímabil`); update `stimpilklukka.html` to filter by `Tímabil` if the mismatch ever matters. Open shifts are excluded (shown as a note).
- **`/eigandi` — owner phone clock-in** ([api/eigandi-clock.js](api/eigandi-clock.js)): the kiosk device lock ties INN/ÚT to being at the shop; owners don't want that. `/eigandi` is `stimpilklukka.html` with `OWNER_MODE` (`location.pathname === "/eigandi"`). The PIN goes to `POST /api/eigandi-clock` which verifies it belongs to an `Eigandi 👨🏻‍💼` and returns `{ token, record, shortcut }`. `token` is `ownerDayToken()` — HMAC of the date keyed with `KIOSK_DEVICE_SECRET`, rotates daily, never exposes the secret; `isKioskPaired()` in `api/airtable.js` accepts today's or yesterday's alongside the real secret, so the page's own Stimplanir/Verktímar writes go through unchanged. `/klukka` and the shop tablet are untouched — no re-pairing.
  - **GPS / Apple Shortcuts**: `POST /api/eigandi-clock?k=<recordId>~<hmac>&action=inn|ut|toggle` clocks in/out server-side with no PIN — for a "When I Arrive" personal automation. POST-only (a link-preview GET can't clock anyone in). `k` is `shortcutToken()`, stable per owner, shown as a copyable URL by the "⚙️ Sjálfvirk stimplun" button after login. No per-owner revoke — rotating `KIOSK_DEVICE_SECRET` kills every token (kiosk + shortcuts).
  - **Catch-up project split**: an auto clock-out (`action:"ut"`) just closes the shift — a Shortcut can't do the interactive Verktímar split. So on `/eigandi` login, `checkCatchUp()` looks for the owner's own closed shifts (last 5 days, not already covered by a `Verktímar` row, not skipped) and opens the split screen for the oldest **day** — all of that day's unsplit shifts in ONE screen (the GPS shortcut makes 3–4 short shifts a day; asking per shift made owners split the same day over and over, fixed 2026-09-29), each Verktímar row links to all of them; a day under 30 min total is skipped silently. A manual ÚT on `/eigandi` also folds that day's earlier unsplit shifts into its split (`unsplitShiftsToday`). "Sleppa" is remembered on the device (`localStorage` `eigandi:skippedCatchUp`), not just the session. `/klukka` (non-owner) never runs this.
- **Kiosk device lock**: INN/ÚT (Stimplanir POST/PATCH) require an `X-Kiosk-Token` header matching the `KIOSK_DEVICE_SECRET` env var — `KIOSK_LOCKED_TABLES`/`isKioskPaired()` in `api/airtable.js`. Sick-marking and vacation requests are untouched, still work from any device. Pairing: visiting `/klukka?setup=<KIOSK_DEVICE_SECRET>` once stores the secret in that browser's `localStorage` and strips it from the URL via `history.replaceState`; re-pairing (revisit the URL) is needed if the tablet's browser data is ever cleared or the tablet is replaced. Closing a shift from `markSick()` (someone was clocked in, then marked sick remotely) is best-effort — it's still a Stimplanir PATCH, so it silently no-ops on an unpaired device rather than blocking the sick-marking itself.

- **`Mánuður 🗓️`/`Ár 🗓️` on Stimplanir are real single-select fields, not formulas** — deliberately, so they work as clean pick-a-value dropdown filters on Interface pages. (A formula/date field only offers Airtable's date-*comparison* filter — is/is before/is after — not a value picker; only checkbox/date/dateTime/select/collaborator/linked-record field types get the dropdown-of-values treatment.) The kiosk computes and sends both directly in `punchAction()`'s POST; `api/airtable.js` sends `typecast: true` so a non-matching choice self-adds rather than hard-failing. `Ár 🗓️` covers 2025–2030. **Payroll filtering now uses `Tímabil 🗓️` instead** (single-select, same reasoning) — set by the `Stimplun → frídagur + tímabil` automation, mirrors the `Tímabil` formula. Choices run to 2028-12 on both `Stimplanir` and `Launatímabil`.
- **Per-project time — `Verktímar 🕒`** (`tblGu27c2fcwN2i2n`): on **ÚT**, `stimpilklukka.html` first PATCHes `Út` onto the shift (so the clock-out is safe even if the next step is abandoned), then shows an allocation screen where the employee splits that shift's hours across the projects they worked on. One `Verktímar` row per slice: `Dagsetning`, `Klst` (worker-entered, 0.5h steps), `Starfsmaður` link, `Verkefni 📣` link (blank for the buckets), `Verkflokkur` (`Verkefni`/`Sölur`/`Annað`), `Stimplun ⏱️` link back to the shift row. Rolls up to `Tækifæri › Vinnutími starfsmanna (klst) 🕒` (SUM) — compare with the estimate `samtals framleiðslutími Rollup ➖📦 (Line item's) klst` — and `Starfsmenn › Verkefnatímar samtals (klst) 🕒`.
  - **Stimplanir is untouched** — still one row per shift, all payroll formulas unchanged. The split lives entirely in the child table. This was a deliberate choice over segmenting Stimplanir into per-project rows (which would have put the dagvinna/yfirvinna/lunch math at risk).
  - **`Klst` is the raw shift duration split**, not paid hours. `Samtals (klst)` is itself just `(Út − Inn)` (no lunch removed), so "divide your Samtals across projects" = divide raw hours. Target is `(Út − Inn)` rounded to the nearest 0.5; the odd minutes ride silently on the project the worker put last. Lunch/pre-08:00 nuance only matters for the dagvinna/yfirvinna split, which stays in Stimplanir.
  - **Which projects show is driven by `Starfsheiti 💼`** (now in Starfsmenn's `ALLOWED_FIELDS`): `Framleiðsla` → active workshop jobs only (won + `Klárt til framleiðslu` + not `Má Afhenda`/`Afhent`); `Sölumaður / Arkitekt` → a `Sölur` bucket + won jobs still in `For-skipulag`/`Í skipulagningu`/`Yfirfara` **plus any `🔥 Líklegt tækifæri` deal** (pre-win design work); every other role → both lists + `Sölur`. Everyone also gets an `Annað` bucket so the split can always reach 100%.
  - **Mandatory**: submit is blocked until the remainder is exactly 0. Escapes that leave the shift closed but the split unwritten (manager fills in on `Verktímar`): a "Sleppa í bili" link shown only if the project list fails to load, and a 120s inactivity timer that frees the kiosk.
  - **Kiosk-device-locked** like Stimplanir — `Verktímar` is in `KIOSK_LOCKED_TABLES`, so the split POSTs need the `X-Kiosk-Token` header (verified: without it → 403 `DEVICE_NOT_PAIRED`).
  - **Rollup precision**: Airtable rollups default to 0 decimals and the API can't set precision — bump `Vinnutími starfsmanna (klst) 🕒` (and the Starfsmenn one) to 1 decimal in the field's formatting UI if the rounding bothers anyone. The underlying value is exact.
  - Replaced the old `/stod` (Vinnustöðvar) page + `Stöðvatímar ⏱️` table, both deleted 2026-08-27 — that kiosk (anonymous Kantlíming/Spónlagning/Lökkun station timing) was never really used (one test row) and this covers the same "how long per project" goal.

## HR / Launakerfi (Airtable — no Vercel)

Built 2026-08. Full chain: clock (`/klukka`) → pay period → dagvinna/yfirvinna split → holiday/sick/orlof pay → frozen monthly close → CSV for the bókari. **No employee sign-off step** — staff just get a payslip (ask for a timesheet → export from `Stimplanir`). Everything lives in Airtable: tables + formulas + one big "Run a script" step in the `MD 🗓️ - DAGLEGT ⏰` automation + one shift-created automation.

### Pay periods — 29th → 28th
- A launatímabil runs **29th of one month to 28th of the next**, labelled by the month it *ends* in (`2026-08` = 29 Jul – 28 Aug), paid the **1st** of the next month.
- Clock-in on days 1–28 → that month's period; days 29–31 → next month's.
- `Stimplanir.Tímabil` (formula) computes it; `Stimplanir.Tímabil 🗓️` (single-select, choices → 2028-12) is the same value for dropdown filtering, set by the `Stimplun → frídagur + tímabil` automation. `Launatímabil` has `Tímabil frá` / `Tímabil til` (dates) + `Tímabil 🗓️`.
- Non-leap February: that period starts 1 Mar (no 29 Feb) → a 28-day period. No days fall through the cracks.

### `Launatímabil 🧾` (`tblSQ0FfGQeBttaH2`) — one frozen row per employee per period
- Shifts + `Fjarvistir` linked in by the automation; hours arrive as rollups (`Dagvinna klst`, `Yfirvinna klst`, `Samtals klst (hrátt)` = raw Út−Inn incl. lunch — *not* payroll basis).
- `Frídagar greitt (klst)` + `Greiðir frídagar` (text list) — **paid public holidays not worked**: 7,5 Mon–Thu / 5,0 Fri / 3,75 half (Framleiðsla); 7,5 any day / 3,0 half (Sölu). Only if employed that date and no shift.
- `Veikindi greitt (klst)` — **first 2 sick days/period** (chronological, half-day = 0,5) paid at that weekday's standard hours; day 3+ unpaid.
- `Dagvinna alls (klst)` = Dagvinna rollup + Frídagar greitt + Veikindi greitt ← **the dagvinna number on the payslip / CSV.**
- `Greiddar klst` = Dagvinna alls + Yfirvinna.
- Króna: `Dagvinnulaun` (Dagvinna alls × `Kaup per klst`), `Yfirvinnulaun` (× `Yfirvinnagjald` = Kaup × 1,56), `Orlofsinneign (kr)` (`Orlofs%` × laun — paid out monthly), `Heildarlaun f. skatt`.
- Workflow: tick `Læst` → the automation copies Dagvinna alls / Yfirvinna / Greiddar / Heildarlaun into the `(læst)` fields (frozen — a paid period never changes). `Orlof-rúllun búin` guards the sick→orlof rollover from double-counting. `Staðfest af starfsmanni` fields exist but are unused.
- The bókari CSV = a grid view filtered `Læst` ✓ + `Tímabil 🗓️`, columns `Nafn · Kennitala · Dagvinna alls (klst) · Yfirvinna klst`, Download CSV. (`Kennitala` source field is a *number* → drops leading zero for anyone born on the 1st–9th.)

### Orlof — real balance on `Starfsmenn`
- Samiðn/Byggiðn seniority ladder: `Menntun` (Ekkert/Í námi/Sveinspróf/Meistarabréf) + `Ár í iðngrein við ráðningu` + `Starfsaldur hjá Björninn (ár)` → `Orlofsþrep` → `Orlofsréttur (dagar)` (24/25/27/28/30) + `Orlofs%` (10,17…13,04). Skilled (sveins/meistara) get the skilled table.
- `Orlofsdagar teknir (þ. orlofsár)` = rollup of `Fjarvistir`'s `Orlofsdagur (vægi)` field (Tegund=Orlof, falling in the current orlofsár — 1 May – 30 Apr, `Er í yfirstandandi orlofsári` helper). That weight formula also zeroes out a row whose `Staða` is `Í bið`/`Hafnað`, so a pending or rejected vacation *request* row never inflates this before it's actually approved. `Orlofsdagar eftir` = réttur + `Orlof frá fyrra ári` + `Auka orlofsdagar 🌴` − teknir.
- **Model**: orlof % is paid out monthly (`Launatímabil.Orlofsinneign`); orlof days are planning/tracking only, they don't pay extra (the money was already paid).
- `Auka orlofsdagar 🌴` = bonus days from unused sick leave (2/month, uncapped days used doesn't go negative, **running balance capped at 10**).

### `Fjarvistir 🤒` (`tbl3e5o0Klv9RcNQ4`)
One row per employee per day. `Tegund` (live choices): Veikindi / Vinnuslys / Launalaust Leyfi / Námsleyfi — plus `Orlof`, which isn't a persisted choice but gets typecast-added the first time a script writes it. + `Hálfur dagur`, `Greitt?`, `Vottorð`, `Athugasemd`.

Also doubles as the vacation-request table since 2026-09-22 (merged in what used to be a separate `Orlofsbeiðnir 🌴` table) — see the "Vacation-request fields" note under the stimpilklukka bullets above for `Staða`/`Til`/`Dagar (virkir)`/`Dögum dreift`/`Orlofsdagar eftir (staða)` and the full request→approval→daily-rows flow.

### Automations
1. **`MD 🗓️ - DAGLEGT ⏰`** (cron 07:00) — its 2nd "Run a script" step is the whole HR engine:
   - **Current period**: build/update `Launatímabil` daily (link shifts + fjarvistir, compute holiday/sick pay).
   - **Uppgjör**: finalize last period *once* (self-heals via `Orlof-rúllun búin`) — sick→orlof (`+MAX(0, 2 − veik)` into `Auka orlofsdagar`, cap 10), then Chat "tilbúið að læsa".
   - **Frysta**: `Læst` ticked → copy into `(læst)` fields.
   - **Reminders → Google Chat** (space `AAQAmeYUzJc`, webhook hardcoded): forgot-to-clock-out, 3+ consecutive sick days, pending vacation requests, approved leave → expands into daily `Fjarvistir` (Orlof) rows, reynslutími/starfsafmæli within 7 days, day 28 (period ends → clock out), day 1 (review & lock), 15 Mar (unused orlof), 1 May / 1 Jun / 1 Dec (orlofsár / uppbætur).
   - `PAYROLL_TYPES = ["Fast ráðinn 👷","Verktaki 👨‍🎨","Lausráðinn "]` — only these get a launatímabil (owners/robot skipped).
   - **The MCP API can't create/edit `customScript` nodes** (`readOnlyNodeType`) — all script changes are handed to the user as paste-in-full or find/replace for the Airtable UI.
2. **`Stimplun → frídagur + tímabil`** (record created on `Stimplanir`) — matches `Inn` date to `Frídagar 📅` → sets `Frídagur` / `Hálfur frídagur`; computes `Tímabil 🗓️`.

### Deal payment split (`Tækifæri`, replaced 2 automations)
`Skipting greiðslu` (single-select: `100%` / `50% - 50%` / `40% - 30% - 30%`) + `Greiðsla 2 greidd` / `Greiðsla 3 greidd` checkboxes + `Greiðsla 1 (staðfesting)` (formula, ✅ once `Staða í söluferli = 🏆 Tækifæri unnið`) → **`Greitt (kr) 💰`** formula (`💰 Tilboðsupphæð` × ticked installment %s) + `Eftirstöðvar (kr) 💰`. Old `Það sem kúnni hefur borgað 💲` / `Eftirstöðvar greiddar` kept but unused. Interface hides Greiðsla 2/3 based on the split.

### Yearly / periodic upkeep
- Add next year's rows to `Frídagar 📅`.
- Extend `Tímabil 🗓️` choices (both `Stimplanir` and `Launatímabil`) before 2029.
- Byggiðn kjarasamningur changes → re-check the orlof ladder days/% (`Orlofsréttur` / `Orlofs%` formulas) and the 62.000 kr orlofsuppbót figure in the daily script.
- Confirm with the bókari periodically: pre-day-start time stays unpaid; orlof paid-out-monthly model; the flat dagvinna/yfirvinna split (no YV1/YV2).

## Dagvinnukvóti (2026-10-30)

Dagvinna/yfirvinna er nú **dagleg kvóta-regla**, ekki fastur gluggi á hverja stimplun: starfsmaður fyllir dagvinnukvóta dagsins (glugginn mínus ólaunað hádegi: 7,5 klst mán–fim, 5 klst fös, Rakel 7,5 alla daga; hálfur frídagur → til 12:00) áður en yfirvinna byrjar. Allar lokaðar stimplanir sama manns sama dag eru lagðar saman í tímaröð. Tími fyrir upphaf dags er áfram hvorki dagvinna né yfirvinna. Helgar og rauðir dagar = bara yfirvinna.
